2. KEY FEATURES & CAPABILITIES
================================================================================

MODEL ARCHITECTURE (FUTR):
  - Backbone: RegNetY (rny002, rny004, rny006, rny008) from TIMM
  - Temporal Processing: Optional T-Deed modules (EDSGP-Mixer) for enhanced temporal discrimination
  - Transformer: 6-layer encoder + 6-layer decoder (configurable)
  - Multi-task: Action anticipation + segmentation + actionness
  - Output Heads:
    * Action classification (batch, n_query, n_classes)
    * Temporal offset prediction (batch, n_query)
    * Optional: Actionness scores (batch, n_query)
    * Optional: Frame-level segmentation (batch, frames, n_classes)

DATASET SUPPORT:
  1. SoccerNet v2 - General action spotting
  2. Ball Action Spotting (BAS) - Ball-centric event detection
  3. Ball Action Anticipation (BAA) - Novel anticipation dataset
  
  Features:
  - Clip-based sampling with configurable stride/overlap
  - Variable observation percentages (e.g., [0.2, 0.3, 0.5])
  - Per-clip ground truth action labels with temporal offsets
  - Class weighting and exclusion
  - Label smoothing and augmentation
  - Support for joint training on multiple datasets

TRAINING FEATURES:
  - Dual optimizer: AdamW + Muon (experimental)
  - LR Scheduler: Linear warmup + Cosine annealing
  - Loss functions: CrossEntropy, label smoothing, BCE
  - CALF matching: Hungarian algorithm for action reordering
  - Checkpoint management: Periodic saves + best model tracking
  - Weights & Biases integration for logging
  - Gradient computation with optional masking

EVALUATION METRICS:
  - mAP@δ: Mean average precision at temporal delta δ
  - mAP@∞: Occurrence within anticipation window
  - Per-class F1 scores
  - Accuracy and error statistics
  - Class-wise TP/FP/FN/TN analysis

5. CONFIGURATION SYSTEM
================================================================================

Each config JSON includes:

Paths:
  • frame_dir: Input frame directory
  • save_dir: Checkpoint save location
  • store_dir: Cache directory for dataset preprocessing

Dataset:
  • dataset: "soccernetballanticipation", "soccernetball", or "soccernet"
  • clip_len: 750 (frames per clip)
  • epoch_num_frames: Total frames per epoch (e.g., 18000)
  • batch_size: Batch size for training
  • num_workers: DataLoader workers

Architecture:
  • feature_arch: "rny002", "rny004", "rny006", or "rny008"
  • temporal_arch: "ed_sgp_mixer" or "none"
  • n_head: 8 (attention heads)
  • hidden_dim: 256 (hidden dimension)
  • n_encoder_layer: 6 (encoder depth)
  • n_decoder_layer: 6 (decoder depth)
  • n_query: 8 (max predictions per frame)

Training:
  • num_epochs: 100
  • learning_rate: 0.001
  • optimizer: "adamw" or "muon"
  • weight_decay: 0.05
  • warm_up_epochs: Number of warmup epochs

Task Configuration:
  • obs_perc: [0.2, 0.3, 0.5] (observation window percentages)
  • pred_perc: 0.3 (prediction/anticipation window percentage)
  • seg: true/false (auxiliary segmentation task)
  • anticipate: true/false (action anticipation task)
  • actionness: true/false (use actionness instead of EOS)
  • use_anchors: true/false (temporal anchor prediction)

Advanced:
  • CALF_matching: true/false (Hungarian algorithm for action reordering)
  • mask_attn: true/false (attention masking)
  • offset_loss_weight: 1.0 (temporal offset loss scaling)
  • class_weights: Per-class loss weighting

6. WORKFLOW - TRAINING TO EVALUATION
================================================================================

Step 1: SETUP
  $ python setup_dataset_BAA.py --download-key YOUR_NDA_KEY
  $ pip install -r requirements.txt

Step 2: TRAINING
  $ python main.py config/SoccerNetBall/Base-Config-BAA.json my_model_v1
  Output: Checkpoints in my_model_v1/ directory
          Logs in wandb (if online mode)

Step 3: EVALUATION
  $ python test.py config/SoccerNetBall/Base-Config-BAA.json \
                   my_model_v1/model/transformer/best_model.pth \
                   my_model_v1 -s test
  Output: Metrics (mAP@δ, mAP@∞, F1, etc.)
          Predictions saved as .npy files

Step 4: CHALLENGE SUBMISSION (optional)
  $ python test.py config/SoccerNetBall/Base-Config-BAA.json \
                   my_model_v1/model/transformer/best_model.pth \
                   my_model_v1 -s challenge
  Output: Challenge submission format

  $ pip install -r requirements_pose.txt

  $ python scripts/run_pose_estimation.py \

      --output output.mp4 \
      --device cuda

  $ python scripts/run_pose_estimation.py \
      --input video.mp4 \
      --output output.mp4 \
      --backend bboxmaskpose \
      --bbox_config config.py \
      --bbox_checkpoint weights.pth \
      --det_config det_config.py \
      --det_checkpoint det_weights.pth

    wrists, hips, knees, ankles)
  - Two backends: KeypointRCNN (default) or BBoxMaskPose (high accuracy)
  - Support for video files or frame directories
  - Adjustable confidence thresholds
  - Visualization options (bboxes, confidence scores)

9. IMPORTANT NOTES
================================================================================

Dataset Limitations:
  - BAA dataset requires NDA from https://www.soccer-net.org/data
  - FFmpeg required for frame extraction
  - ~100+ GB storage needed for full dataset with frames
  - SoccerNet v2 data access also requires NDA

Model Checkpoints:
  - Training checkpoints: Saved every epoch (with optimizer/scheduler state)
  - Best model checkpoint: Only weights saved (best mAP)
  - Can resume training from any epoch checkpoint

Evaluation:
  - Predictions are clipped-based
  - Metrics calculated per game/video
  - Challenge splits have slightly different evaluation protocol
  - Test split evaluation creates .npy prediction files for debugging

Performance:
  - Code tested on NVIDIA NGC PyTorch container (torch 2.8.0a0)
  - GPU recommended (tested on NVIDIA A100)
  - CPU mode available for small-scale testing

Reproducibility:
  - All randomization can be controlled via seed
  - Deterministic=true removes non-deterministic operations
  - Config fully specifies model and training
